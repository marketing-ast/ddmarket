# Категории и постоянные ID

Сотрудник добавляет пары в `categories!A:B`. Отдельный сервис на существующем
сервере DD Market проверяет таблицу каждые 15 секунд через сервисный аккаунт
импортёра. Обычно результат виден за 15–30 секунд. Apps Script и личная сессия
Google владельца не используются. Не запускать параллельно другой генератор ID.

## Для сотрудника

1. В новой строке `categories` заполнить `category0` и `category1`.
   Для подкатегории выбрать существующую категорию в A. Для нового раздела ввести
   новое название в A и первую подкатегорию в B. Можно вставить несколько строк.
2. Подождать 15–30 секунд. Коды и порядок заполнятся в скрытых колонках C:F.
3. В `products` выбрать категорию в G. После обновления списка выбрать подкатегорию
   в H. При смене категории нужно снова выбрать подходящую подкатегорию.
4. У нового товара заполнить название, штрихкод и единицу измерения. Если его ID
   пуст, сервис выдаст следующий свободный номер. Пустой `publish` станет `no`.
   Затем заполнить цену/остаток и разрешить публикацию обычным способом.

Существующие резервные строки с ID можно использовать как раньше. Перемещение
товара в другой раздел не меняет его ID. Переименование существующей пары требует
отдельного переноса: для добавления нового раздела использовать пустую строку,
не заменять старую. Ошибки показываются в примечании к `categories!A1`.

Сайт получает CSV `products` (gid=0) и порядок из CSV `categories` (gid=1001).
Видимая открытая вкладка проверяет обновления каждые пять минут. Публикация Google
может добавить задержку. Пустые разделы скрыты. Если справочник ещё не обновился,
новые категории товаров всё равно отображаются в конце меню.

## Сохранность данных

- Существующие непустые ID никогда не переписываются. Дубли ID останавливают обработку.
- `_ddmarket_category_ids` хранит выданные префиксы и максимальные номера, включая
  удалённые товары/категории. Реестр защищён и скрыт; удалять его нельзя.
- Выдача ID, обновление счётчиков и списков выполняются одним атомарным запросом
  Google Sheets. После неизвестного результата запроса данные сначала читаются заново.
- Перед записью повторно проверяется состояние таблицы. При изменении исходных
  строк обработка откладывается до следующего прохода. Сервис защищён файловой
  блокировкой от одновременного запуска второй копии.
- Столбец `products.id`, `categories.C:F` и служебные листы защищены. Владелец по
  правилам Google сохраняет возможность редактировать их вручную.
- Цены, штрихкоды, фотографии и остатки не переписываются. Формула остатка создаётся
  только в пустой ячейке нового товара, которому только что выдан ID.
- Неполные пары/товары не получают код до заполнения необходимых полей.
- Дубли имён с отличиями только в регистре/пробелах отклоняются. Одинаковые
  подкатегории допустимы у разных родителей.
- Сохраняется формат: префиксы 01–99, номера 0001–9999 внутри каждого. Переполнение
  останавливает выдачу с сообщением, не меняя существующие ID.
- Периодическая проверка каждые пять минут восстанавливает правила списков.
  Сервис работает и при закрытой таблице; импортёр остатков работает независимо.

## Код и проверки

`scripts/category_sync.py` — планировщик, запросы Sheets и серверный цикл.
`scripts/ddmarket-category-sync.service` — systemd unit с уже существующим
окружением `/opt/ddmarket-import-bot/.env`. Новые ключи доступа не создаются.

```sh
node --test tests/site_catalog.test.mjs
python -B -m unittest discover -s tests -p test_category_sync.py -v
```

Перед первым запуском требуется нативная резервная копия таблицы и проверка на
отдельной тестовой копии. Сервисный аккаунт должен иметь доступ к тестовой копии.
Диагностика без записи:

```sh
/opt/ddmarket-import-bot/.venv/bin/python -B /opt/ddmarket-import-bot/scripts/category_sync.py \
  --env-file /opt/ddmarket-import-bot/.env --dry-run
```

Однократное применение: заменить `--dry-run` на `--once`. Для тестовой копии добавить
`--spreadsheet-id <ID копии>`. В systemd unit рабочий ID указан явно; однократный
запуск без этого параметра использует окружение бота или основной ID по умолчанию.
При первом применении сохраняется также JSON снимок на сервере в
`/opt/ddmarket-import-bot/backups/categories/` с правами 0600.

```sh
systemctl status ddmarket-category-sync.service
journalctl -u ddmarket-category-sync.service -n 30 --no-pager
```

Для отката остановить и отключить только `ddmarket-category-sync.service`.
Не удалять реестр и не возвращать старый столбец ID после добавления новых товаров.
Правила и оформление восстанавливать из резервной копии адресно, сохраняя новые
товары, цены и остатки. Если сервис меняется на Apps Script, сначала остановить
сервис и перенести реестр — одновременно два генератора работать не должны.

## Публикация сайта

Основной домен `ddmarket.kz` обслуживает nginx на существующем VPS из
`/srv/ddmarket-site/current`. GitHub Pages публикует отдельную копию: успешный
workflow сам по себе не обновляет основной домен.

При установке 2026-10-28 исходный release `releases/20260620013417` сохранён.
Его полная копия с обновлёнными `app.js` и `index.html` опубликована как
`releases/20261028-categories-61b5a6d`; ссылка `current` переключена атомарно.
В HTML изменён параметр версии скрипта, чтобы браузеры загрузили новый код.
Проверено совпадение публичного `https://ddmarket.kz/app.js?v=20261028-categories`
с кодом репозитория. Для отката фронтенда можно переключить `current` на предыдущий
release; это не меняет таблицу и её реестр ID.
