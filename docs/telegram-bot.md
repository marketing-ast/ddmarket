# Telegram-бот DD Market

Основной код сервиса `ddmarket-import-bot.service` хранится в
`/opt/ddmarket-import-bot/scripts/`. `telegram_import_bot.py`, `sheets_update.py` и
`import_merge.py` перенесены в репозиторий из рабочей версии сервера; ключи и `.env`
не копируются. Зависимости зафиксированы в `requirements-bot.txt`.

## Работа сотрудников

В разрешённой группе каждый сотрудник может нажать «Ввести ручной остаток» или
«Загрузить отчёт 1С». Если своего сеанса ещё нет, он создаётся автоматически.
`/start@DDMarket_pricer_bot` перезапускает только собственный сеанс;
`/stop@DDMarket_pricer_bot` закрывает только его. Сеанс истекает через 30 минут.

Промежуточные кнопки относятся к сотруднику и конкретному шагу. Чужие, старые и
повторные подтверждения не меняют данные. Старые кнопки подтверждения, созданные
до установки исправления, нужно заменить новым проходом через меню.

## Причины сбоя и защита от конфликтов

- Раньше состояние хранилось по ID группы. Новый `/start` заменял сеанс предыдущего
  сотрудника и приводил к отказу «Этот сеанс начал другой пользователь». Теперь ключ
  включает группу и сотрудника, файлы и отчёты также разделены и имеют уникальные имена.
- Ошибка Telegram HTTP 400 при `answerCallbackQuery` раньше завершала процесс.
  Ответ на просроченную кнопку теперь безопасно отклоняется; её действие не выполняется.
  При старте процесса приветствие не рассылается. Обычные сообщения группы игнорируются.
- Один процесс удерживает `temp/telegram-import-bot/process.lock`. Обработчики и записи
  выполняются последовательно. Второй экземпляр бота с тем же рабочим каталогом не стартует.
- Номер следующего события сохраняется атомарно перед обработкой. После сбоя событие
  не воспроизводится автоматически: при неизвестном исходе пользователь проверяет данные
  и повторяет операцию новым действием. Это предотвращает автоматическое повторное применение,
  но не даёт гарантии выполнения прерванной операции.
- Ручной остаток сверяется с показанным значением и единицей измерения, ID и штрихкодом.
  Есть повторная проверка перед записью и чтение результата. Второй сотрудник получает
  конфликт, если первый уже изменил выбранный остаток.
- Подтверждение импорта связано с конкретным файлом и снимком значимых колонок.
  Изменение данных после проверки требует нового отчёта и подтверждения. Права на
  подтверждение скачка цен больше 20% и проверка полноты выгрузки сохранены.

Google Sheets не предоставляет условную запись по версии диапазона. Очередь и
блокировка защищают сотрудников, работающих через этого бота. Между последней
проверкой и записью остаётся небольшой интервал для внешнего редактора таблицы;
строгая транзакционная изоляция от ручных правок требует единого пути записи или БД.
Не запускать сторонний писатель этих же полей параллельно боту.

## Проверки и установка

```sh
python -B -m unittest discover -s tests -p 'test_*.py'
node --test tests/site_catalog.test.mjs
```

Перед установкой: проверить код в окружении сервера и полный сценарий двух
сотрудников на тестовой копии Sheets, подменив отправку Telegram-сообщений.
Остановить только `ddmarket-import-bot.service`, сохранить исходники и `state.json`,
атомарно заменить исходники и запустить сервис. Старый сеанс переносится владельцу.
Проверить `NRestarts`, API `getMe` и журнал. Не запускать второй `getUpdates` для проверки.

Исправление установлено 2026-10-28. Резервная копия двух исходников и исходного
`state.json`: `/opt/ddmarket-import-bot/backups/bot-sessions-20261028/`.
Проверены два независимых сотрудника на тестовой копии, чужое подтверждение,
конфликт ручных остатков и сохранение ID; сообщения в рабочую группу не отправлялись.
На рабочем токене проверены `getMe` и безопасная обработка ошибочного callback ID.

При откате учитывать формат состояния v2: старый код не понимает персональные сеансы
и `next_update_id`. Не подставлять в него новый `state.json` и не воспроизводить старые
подтверждения. Резервная копия исходного состояния сохраняется отдельно.

Протокол: [Telegram Bot API — getUpdates](https://core.telegram.org/bots/api#getupdates),
[answerCallbackQuery](https://core.telegram.org/bots/api#answercallbackquery).
